# pki-lite: repository rules

pnpm monorepo: `packages/pki-lite` (the library) and `packages/pki-lite-crypto-extended`
(algorithms WebCrypto lacks). Read `CONTRIBUTING.md`; the rules below are the ones it and
the tooling enforce, plus conventions the existing code follows.

## Source and tests

- Every source file has a test file next to it: `src/x509/Foo.ts` ->
  `src/x509/Foo.test.ts`. Only barrels (`index.ts`), type-only files (`types.ts`) and
  error classes are exempt. Tests cover construction, parsing, edge cases/errors and DER
  round-trips (parse -> serialize gives the same bytes).
- Tests run in two vitest projects: `node` and `browser` (Chromium via Playwright).
  Anything outside `test/node/` must be browser-safe: no `Buffer`, `fs`, `node:*` or
  other Node APIs (use `Uint8Array`, `atob`, `TextEncoder`, `crypto.subtle`). Node-only
  tests (OpenSSL CLI, filesystem, the examples smoke test) go in `test/node/`.
- Other test folders: `test/unit/` (cross-cutting unit tests, e.g. the OpenSSL corpus
  audit), `test/integration/`, `test/acceptance/`.
- OpenSSL corpus (`test-fixtures/openssl-corpus/`): `corpus.ts` is generated by
  `generate.sh`; never edit it by hand. Failing cases go in `KNOWN_ISSUES` in
  `test/unit/openssl-corpus.test.ts` (they run as `test.fails`); delete the entry in the
  same change that fixes it.

## Code

- Placement: the standard folders (`x509/`, `x509/extensions/`, `pkcs7/`, `asn1/`,
  `keys/`, ...) hold only PKI/ASN.1 structures. Everything else (validation logic,
  helpers, builders, crypto providers) goes under `src/core/`, e.g.
  `core/NameConstraintsChecker.ts` next to `core/CertificateValidator.ts`.
- Every class for an ASN.1 structure has the ASN.1 definition in its JSDoc under `@asn`
  (fenced as `asn`).
- Class layout: public ASN.1 fields, constructor taking an options object, static
  factories (`fromAsn1`, plus `fromDer`/`fromPem` where the type is a top-level
  structure), then `toAsn1`/`toDer`/`toPem`. Extend `PkiBase` (or `PkiSequence`/`PkiSet`).
- Byte arrays are typed `Uint8Array<ArrayBuffer>`.
- ASN.1 tagging: the X.509/CMS/TSP modules use IMPLICIT TAGS, so `[n] Type` fields are
  implicitly tagged; only tagged CHOICEs (e.g. `directoryName [4] Name`) are explicit.
  DER: omit DEFAULT values, minimal INTEGERs and named bit lists.
- OIDs live in `src/core/OIDs.ts` (with a friendly name in its name table); use the
  constants in library code rather than OID strings.
- New crypto: algorithm OID in `OIDs.ts`, parameters class in `src/algorithms/`,
  wiring in `AlgorithmIdentifier`, operations in `WebCryptoProvider`. Algorithms
  WebCrypto can't do (RSA PKCS#1 v1.5 encryption, 3DES, Ed448, ...) belong in
  `pki-lite-crypto-extended` (`WebCryptoExtendedProvider`), not the core package.
- Keep dependencies minimal; the core must work in browsers and Node.

## Examples and docs

- New features and public APIs need a runnable example in `examples/`, named
  `NNN-short-name.ts` (next free number), whose first line is a `// Title` comment.
- Add self-contained (offline) examples to the list in
  `packages/pki-lite/test/node/examples.test.ts`, which runs them against `dist`.
- After changing examples, regenerate `EXAMPLES.md` with `pnpm compile:examples`; don't
  edit it by hand. `docs/` is generated by typedoc (`pnpm docs:gen`).

## Formatting, commits, releases

- Prettier (`.prettierrc`: 4 spaces, no semicolons, single quotes, trailing commas).
  The husky pre-commit hook formats staged files; run git inside an environment that
  has pnpm so the hooks work.
- Conventional Commits, checked by commitlint (`.commitlintrc.cjs`). Allowed types: `ci`,
  `feat`, `fix`, `refactor`, `revert`, `style`, `chore`, `docs`, `test`, `bump`, `perf`,
  `security`, `release`. The subject must not be sentence/start/pascal/upper case: write
  acronyms in lower case (`fix(cms): ...rfc 5652...`).
- A merge to `master` publishes only when its commit message starts with
  `release(...):` (see `.github/workflows/release.yaml`); use the prepare-release
  workflow for that, not hand-written release commits.

## Commands

```sh
pnpm install
pnpm compile                         # all packages, examples and type checks
pnpm test                            # every package, node + browser
cd packages/pki-lite
pnpm test:unit                       # src/ only
pnpm vitest run --project node       # or --project browser
```
