# NIST PKITS (sections 4.8 to 4.13)

Certificates and certification paths from the NIST Public Key Interoperability Test Suite
(PKITS), used by `test/unit/pkits.test.ts` to check certification path validation
against an independent, widely used reference:

| Section | Tests | Subject               |
| ------- | ----- | --------------------- |
| 4.8     | 20    | Certificate policies  |
| 4.9     | 8     | requireExplicitPolicy |
| 4.10    | 14    | Policy mappings       |
| 4.11    | 11    | inhibitPolicyMapping  |
| 4.12    | 10    | inhibitAnyPolicy      |
| 4.13    | 38    | Name constraints      |

Source: <https://csrc.nist.gov/projects/pki-testing> (`PKITS_data.zip` and `PKITS.pdf`,
version 1.0.1). PKITS is a work of the US government (NIST) and is not subject to
copyright in the United States.

`pkits.ts` is generated by `generate.sh`; don't edit it by hand. It holds only the
certificates these sections use (`file name -> base64 DER`) and, for each test, the
certification path the specification lists, trust anchor first and end entity last, so
the test runs in both the node and the browser vitest projects. CRLs are left out: these
sections test policy and name processing, not revocation.

The expected results are not in the data: they are transcribed by hand from
`PKITS.pdf` into `test/unit/pkits.test.ts`, including the extra input settings
(initial-policy-set, initial-explicit-policy, ...) the specification asks for.

To regenerate (the downloads are pinned by SHA-256):

```sh
./generate.sh    # needs curl, unzip, sha256sum, pdftotext (poppler) and python3
```
