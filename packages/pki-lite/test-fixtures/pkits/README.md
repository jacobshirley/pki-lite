# NIST PKITS

Certificates, CRLs and certification paths from the NIST Public Key Interoperability Test
Suite (PKITS), used by `test/unit/pkits.test.ts` to check certification path validation
against an independent, widely used reference. It covers every test in section 4:

| Section | Tests | Subject                        |
| ------- | ----- | ------------------------------ |
| 4.1     | 6     | Signature verification         |
| 4.2     | 8     | Validity periods               |
| 4.3     | 11    | Name chaining                  |
| 4.4     | 21    | Basic certificate revocation   |
| 4.5     | 8     | Self-issued certificates       |
| 4.6     | 17    | Basic constraints              |
| 4.7     | 5     | Key usage                      |
| 4.8     | 20    | Certificate policies           |
| 4.9     | 8     | requireExplicitPolicy          |
| 4.10    | 14    | Policy mappings                |
| 4.11    | 11    | inhibitPolicyMapping           |
| 4.12    | 10    | inhibitAnyPolicy               |
| 4.13    | 38    | Name constraints               |
| 4.14    | 35    | Distribution points            |
| 4.15    | 10    | Delta-CRLs                     |
| 4.16    | 2     | Private certificate extensions |

Source: <https://csrc.nist.gov/projects/pki-testing> (`PKITS_data.zip` and `PKITS.pdf`,
version 1.0.1). PKITS is a work of the US government (NIST) and is not subject to
copyright in the United States.

`pkits.ts` is generated by `generate.sh`; don't edit it by hand. It holds the certificates
and CRLs the tests use (`file name -> base64 DER`) and, for each test, the objects the
specification lists for its certification path (trust anchor first, end entity last), so
the test runs in both the node and the browser vitest projects.

`pkits-smime.ts` (also generated) holds the S/MIME message PKITS provides for each test
("Signed Test Message 6.2.2.x"): its signed content and its detached CMS signature, which
carries the signer's certificates and the CRLs of its path. The test verifies each message
with SignedData.verify and the trust anchor, and expects the same result as the test's
certification path.

The expected results are not in the data: they are transcribed by hand from `PKITS.pdf`
into `test/unit/pkits.test.ts`, including the extra input settings (initial-policy-set,
initial-explicit-policy, ...) the specification asks for. Tests pki-lite does not pass
yet are listed in its `KNOWN_ISSUES`, each with the reason.

To regenerate (the downloads are pinned by SHA-256):

```sh
./generate.sh    # needs curl, unzip, sha256sum, pdftotext (poppler) and python3
```
